Prove the firewall

Real connections, three network namespaces

Each namespace listens on 22, 8080 and 9000, so a blocked connection is blocked by the rules and not by a closed port. Results below are from the CI run, not simulated.

Before the rules are loaded, ot to ingest:8080 and ingest to ot:22 both connect. A 1 MiB payload pushed from the control host arrives with a matching checksum. Drop counters after the run: inbound 6, egress 7.

I/O regression gate

Slower than the baseline? The build fails.

fio runs a 1 MiB sequential write and a 4 KiB random read, O_DIRECT. The gate compares bandwidth and p99 latency with a stored baseline. The capped run is the same job with --rate_iops=50. These are loop-backed devices on a shared runner, so the numbers show the method, not hardware speed.

Same sequential write over NFSv4.2 to localhost: 124.1 MiB/s, p99 333.447 ms. Localhost proves the mount options and plumbing, not network behaviour.

What each part shows

Real, tested, and where it stops

Storage tiers

ansible/roles/storage

mdadm RAID 10, LVM, XFS, ZFS mirror (lz4, 1M records). Built twice, second run changes nothing. Loop files, not NVMe. No BeeGFS.

NFS

ansible/roles/nfs

NFSv4.2, TCP, hard, 1 MiB transfers, nconnect=4. The validator fails soft, v3 or small-transfer mounts. Localhost only. No 100GbE, no RoCE.

Push-only firewall

firewall/ot-push-only.nft

Policy drop in input, forward and output; one allowed outbound. Proven in namespaces. Not a real switch or VLAN.

Kernel tuning

90-ingest.conf

Buffers, backlog, dirty ratios. Applied by Ansible and audited for drift. Starting values, not measured on 100GbE.

fio gate

src/ingestlab/bench.py

Bandwidth and p99 against a baseline; a capped run must fail. A shared runner is noisy, so CI limits are wide.

Validation

bin/node-validate

Shellcheck-clean Bash: sysctl drift, mounts, NFS options, RAID, ZFS, firewall. Exit 1 on any failure. JSON mode.

Slurm

ansible/roles/slurm

One node as controller and compute, the benchmark runs as a batch job. No multi-node, no accounting, no PBS.

RHEL family

CI job

Hardware-free roles run twice on Rocky Linux 9. Not licensed RHEL.

Not covered

honest list

No racking or cabling. No 100GbE, RoCE or BeeGFS. No NVMe tuning. No vendor BOMs. Kafka and Redis are in separate labs.

Decisions and trade-offs

Why this and not that

All design-only: nothing here ran in production.

RAID 10 over RAID 5 or 6
WhyNo parity write penalty, fast rebuilds.
CostsHalf the capacity is gone.
Flip whenCapacity per rack unit matters more than write latency.
ZFS mirror over mdadm and XFS
WhyChecksums, snapshots, compression, scrubs.
CostsRAM for the ARC, CPU, an out-of-tree module on Linux.
Flip whenRaw speed matters more than integrity checks.
Hard NFS mounts over soft
WhyA soft mount can return an error and lose writes.
CostsA hung server blocks clients.
Flip whenA failed write is better than a hang.
Stateful firewall with drop over a hardware data diode
WhyFlexible and testable in CI.
CostsA diode gives a physical one-way guarantee; rules do not.
Flip whenA regulation or threat model needs physical one-way.
Silent drop over reject
WhyTells a scanner nothing.
CostsDebugging is slower.
Flip whenThe segment is internal and fast failure helps.
p99 latency in the gate over averages
WhyShows stalls that an average hides.
CostsNeeds more samples to be stable.
Flip whenThe workload is throughput-only batch.

Run it

Tests in a minute, the full node in a VM

Tests need Linux with root, nftables, iproute2 and fio. The Ansible build needs a Linux machine you do not mind changing (it creates md, LVM, ZFS and NFS state).

git clone https://github.com/gerardrecinto/ingest-node-lab
cd ingest-node-lab
sudo apt-get install -y nftables iproute2 fio python3-pytest
sudo python3 -m pytest -q
sudo PYTHONPATH=src python3 -m ingestlab fw
